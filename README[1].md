# QuizRoom — веб-приложение для квизов в реальном времени

Рабочий MVP-прототип: организатор создаёт квиз и запускает его в комнате
по коду, участники подключаются и отвечают синхронно на каждый вопрос,
система считает баллы и показывает лидерборд.

## Стек

- **Backend:** Node.js, Express, Socket.IO
- **База данных:** SQLite (файл `server/dev.db`) через `better-sqlite3`,
  доступ — через обычный SQL (`server/src/schema.sql`, `server/src/db.js`).
  Схема спроектирована так, что для перехода на PostgreSQL достаточно
  заменить слой доступа к данным — структура таблиц не меняется.
- **Frontend:** HTML, CSS, JavaScript + [Alpine.js](https://alpinejs.dev/)
  (лёгкий реактивный фреймворк, подключается через CDN, без сборки).
  Реальное время на клиенте — `socket.io-client` (тоже через CDN).
- **Аутентификация:** JWT (для организаторов). Участники подключаются
  по коду комнаты без обязательной регистрации.

Backend отдаёт и API, и статику фронтенда одним процессом — деплоить
и запускать нужно только `server/`.

## Запуск

```bash
cd server
npm install
npm start
```

Откройте http://localhost:4000

По умолчанию используется `server/.env` (уже в комплекте, с dev-значениями):

```
DATABASE_URL="file:./dev.db"
JWT_SECRET="dev_super_secret_change_me"
PORT=4000
```

Для продакшна замените `JWT_SECRET` на случайную строку и не коммитьте `.env`.

База данных создаётся автоматически при первом запуске (файл `server/dev.db`).
Чтобы начать с чистого состояния — удалите `server/dev.db*` и перезапустите сервер.

## Как пользоваться

1. **Организатор** регистрируется на главной странице → попадает в «Мои квизы»
   → создаёт квиз → добавляет вопросы (текстовые/с изображением,
   один или несколько правильных ответов) → жмёт «Запустить квиз».
2. Открывается **панель ведущего** с кодом комнаты и списком подключившихся.
3. **Участники** заходят на главную страницу, вводят код комнаты и имя —
   без регистрации.
4. Организатор жмёт «Начать квиз» — все участники одновременно видят
   первый вопрос с таймером и отвечают. Ответ засчитывается только пока
   вопрос активен.
5. По истечении времени (или когда ответили все) вопрос закрывается,
   показывается правильный ответ и обновлённый лидерборд; организатор
   переходит к следующему вопросу.
6. После последнего вопроса — итоговый лидерборд у всех участников
   и у организатора.
7. История проведённых и пройденных квизов — на странице «История»
   в кабинете организатора.

## Структура проекта

```
server/
  src/
    index.js          # точка входа: Express + Socket.IO
    schema.sql         # SQL-схема БД
    db.js               # подключение к SQLite и применение схемы
    auth.js             # JWT, хэширование паролей, middleware
    routes/
      auth.js           # регистрация/вход
      quizzes.js         # CRUD квизов и вопросов
      rooms.js            # запуск комнаты, история
    socket/
      roomManager.js       # вся живая механика: лобби, вопросы, ответы, баллы
    utils/
      id.js, roomCode.js, scoring.js
public/
  index.html            # вход/регистрация + подключение к комнате по коду
  organizer.html         # кабинет организатора: список квизов
  quiz-editor.html         # редактор квиза: настройки + вопросы
  host.html                  # панель ведущего во время игры
  play.html                    # экран участника
  history.html                  # история проведённых/пройденных квизов
  css/style.css                  # дизайн-система
  js/api.js                       # клиент REST API
```

## Известные ограничения прототипа

- SQLite вместо PostgreSQL — осознанный выбор для локального запуска
  без внешней инфраструктуры; структура таблиц готова к переносу.
- Изображения к вопросам подключаются по внешней ссылке (URL),
  без загрузки файлов на сервер.
- Один процесс = одна комната в памяти для таймеров; для продакшна
  с большой нагрузкой таймеры вопросов стоит вынести в отдельный
  воркер/очередь.
